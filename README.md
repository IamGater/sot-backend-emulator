# sot-rare-backend-emulator

Локальный сервер-эмулятор бэкенда Sea of Thieves ("Athena",
`msrareservices.com`) — чтобы старый клиент игры общался с этим сервером
вместо настоящего, ныне частично недоступного бэкенда.

Отдельный, самодостаточный репозиторий — извлечён из более крупного
проекта `sniffer`, содержит только то, что нужно для реальной работы
бэкенда (без логов, дампов памяти, экспериментальных Frida-скриптов и
прочих временных файлов расследования).

## Как это устроено

Игра при старте стучится на **один захардкоженный хост**,
`discovery.prod.athena.msrareservices.com` (`config.DISCOVERY_HOST`), и
получает в ответ JSON-карту `сервис -> {"url": "..."}`, где живут все
остальные сервисы (`catalog`, `login`, `commerce`, `pirate`, `ship`,
matchmaking и т.д.) — реальный бэкенд отдаёт один из нескольких
взаимозаменяемых кластеров (`stamp1`/`stamp3`/`stamp6`/...) при каждом
запросе. Раз этот ответ формируем мы сами, подделывать десятки хостов не
нужно: `discovery.py` переписывает **все** URL из `discovery_full.json`
(реальная захваченная карта сервисов) на один и тот же хост
(`config.REWRITE_HOST` = тот же `DISCOVERY_HOST`), различая сервисы только
путём — в реальной карте пути у сервисов не пересекаются (`/ares/*`,
`/catalog/app/`, `/redeem/app/`, ...), кроме `bridge`/`bridge2`, у которых
в оригинале одинаковый путь `/ws` на разных хостах — здесь им явно
назначены разные пути (`/ws/bridge`, `/ws/bridge2`).

Значит, чтобы весь трафик игры пошёл на эмулятор, достаточно перенаправить
**этот один хост** на `127.0.0.1` — см. «Запуск» ниже. Два хоста
(`sessiondirectory.xboxlive.com`, `rta.xboxlive.com`) — реальная, до сих
пор живая инфраструктура Microsoft/Xbox Live — эмулятор их не подделывает,
а прозрачно проксирует (`session_proxy.py`), патча только отдельные поля
ответа.

Ответы на конкретные запросы эмулятор берёт в таком порядке:

1. **`emulator/handlers/`** — явный питоновский код для конкретного
   `(метод, путь)`, для всего, что требует логики, а не просто повторного
   проигрывания старого ответа (пример: `login.py`).
2. **`emulator/fixtures/data/`** — статичный повтор реального пойманного
   ответа, сгенерированный `extract_fixtures.py` из `flows.jsonl`.
3. **заглушка** — пустой `200 {}`, если ни того ни другого нет (чтобы
   клиент получил хоть что-то разбираемое, а не обрыв соединения).

Оба websocket-моста (`bridge`/`bridge2`, `wss://.../ws`) сейчас — просто
живое соединение без разбора реального фрейм-протокола: эмулятор
принимает апгрейд и держит сокет открытым — см. «Известные пробелы».

## Структура репозитория

```
ca.py                    — генерация корневого CA + on-the-fly leaf-сертификатов
discovery_full.json      — реальная захваченная карта discovery-сервиса
certs/                   — корневой сертификат (НЕ в git, см. .gitignore)
emulator/
  run.py                 — точка входа
  config.py              — центральная конфигурация (хосты, пути)
  discovery.py           — подделка discovery-ответа
  tls_cert.py            — TLS-контекст (переиспользует ../ca.py и ../certs)
  app.py                 — aiohttp-сервер, маршрутизация
  fixtures.py            — загрузка/поиск статичных фикстур
  extract_fixtures.py    — офлайн-инструмент: flows.jsonl -> fixtures/data/
  bridge_state.py        — состояние websocket-мостов (bridge/bridge2)
  rta_proxy.py           — проксирование rta.xboxlive.com
  session_proxy.py       — проксирование sessiondirectory.xboxlive.com
  hosts_redirect.py      — вкл/выкл редиректа в hosts-файле
  handlers/               — явная логика по (метод, путь): login, custom game, contest matchmaking
  gameserver/server.py   — заготовка локального dedicated-сервера (см. его же docstring)
  fixtures/data/         — сами фикстуры (НЕ в git, см. .gitignore)
```

## Установка

Нужен **Python 3.11+**.

```bash
pip install -r emulator/requirements.txt
```

## Запуск

1. **(если фикстур ещё нет / нужно пересобрать)** собрать фикстуры из
   реально пойманного трафика (`flows.jsonl`, например с помощью основного
   `sniffer`-прокси — не входит в этот репозиторий):
   ```bash
   cd emulator
   python extract_fixtures.py
   ```
2. Установить и довериться `certs/rootCA.cer` как корневому сертификату
   (если его ещё нет на диске — `ca.py` сгенерирует новый при первом
   запуске `run.py`, и довериться нужно будет уже ему):
   - **Windows, PowerShell (без прав администратора)**:
     ```powershell
     Import-Certificate -FilePath "certs\rootCA.cer" -CertStoreLocation Cert:\CurrentUser\Root
     ```
   - **Windows, через проводник**: двойной клик `rootCA.cer` →
     «Установить сертификат» → «Текущий пользователь» → «Поместить все
     сертификаты в следующее хранилище» → «Доверенные корневые центры
     сертификации».
   - Полностью закройте и заново откройте игру после установки — список
     доверенных корней читается при старте, не на лету.
3. Прописать редирект (нужен **администраторский** PowerShell/cmd —
   правит `C:\Windows\System32\drivers\etc\hosts`):
   ```bash
   cd emulator
   python hosts_redirect.py on
   ```
   Проверить: `python hosts_redirect.py status`. Выключить, когда закончили
   играть/тестировать: `python hosts_redirect.py off` — иначе именно этот
   один хост игры продолжит указывать на локальную машину, и настоящий
   бэкенд для него останется недоступен.
4. Запустить сервер (слушает `:443`, обычный запуск без прав администратора
   на Windows это позволяет):
   ```bash
   cd emulator
   python run.py
   ```
5. Запустить игру. Дальше можно перейти в
   [sot-openlevel-toolkit](../sot-openlevel-toolkit) — обход matchmaking
   через Frida, вход в открытый мир.

## Известные пробелы

Это каркас, а не полная реализация бэкенда — покрывает столько, сколько
успело попасть во фикстуры на момент их генерации:

- **`POST /ares/login/`** отвечает через `handlers/login.py` полноформенным
  PlayFab `LoginResult` (`SessionTicket`/`EntityToken`/`PlayFabId`...), а не
  голым `{}` — на практике голого `{}` старому билду оказалось
  недостаточно: он просто зацикливался на `discovery → login → login`, не
  доходя до пирата. **`PLAYFAB_ID` в этом файле обязан совпадать** с id,
  зашитым в пути всех остальных фикстур (`.../user/<PlayFabId>/...`) —
  если пересоберёте фикстуры под другой аккаунт, поменяйте константу там
  же.
- **`bridge`/`bridge2` — просто открытый сокет**, без разбора реального
  фрейм-протокола (там наверняка что-то бинарное/protobuf для realtime
  игровых событий). Расширять в `emulator/app.py: bridge_ws`.
- **`maelstrom1`/`maelstrom2`** (матчмейкинг/сессии игровых серверов на
  `athenaprod.maelstrom.gameservices.xboxlive.com`) переписаны на
  `REWRITE_HOST` вместе со всеми остальными, но реальных вызовов на них
  во фикстурах нет — ответы пойдут через заглушку `{}`.
- Предположение «клиент хардкодит только один хост (discovery)» сделано на
  основе имеющегося `discovery_full.json` — если более полный захват
  трафика покажет, что что-то ещё обращается к хосту напрямую в обход
  discovery, его нужно будет так же прописать в hosts и добавить в
  `config.py`/`discovery.py`.
- **Матчмейкинг не завершается по-настоящему** (реальная Xbox Live сессия
  создаётся, но её поле `servers` всегда приходит пустым — нет
  Rare-хостящегося dedicated-сервера, который мог бы туда
  зарегистрироваться). Обход этого для входа в открытый мир —
  см. [sot-openlevel-toolkit](../sot-openlevel-toolkit).
- **Почти все фикстуры бесполезны для экипировки/инвентаря пирата** —
  `pirate`, `pirateslot*`, `loadout`, `commercev2/entitlement`, `ship`,
  `shiploadout`, `emblemv3` и т.д. все помечены `"X-Encoding": "sot"` —
  собственное AES-GCM шифрование Rare поверх TLS, ключ (`GConfig
  [OnlineSecurity] DefaultKey`) так и не был найден, а сами фикстуры к тому
  же захвачены с ДРУГОЙ версии клиента (2.150.9409.0) — так что даже с
  ключом это, скорее всего, был бы не тот ключ. На практике это означает,
  что игрок при заходе в мир не имеет ни оружия, ни инструментов, ни
  эмоций — сервер отдаёт нерасшифровываемые байты, что для клиента
  неотличимо от пустого ответа. **Обошли для `loadout`**:
  `handlers/loadout.py` отвечает НЕЗАШИФРОВАННЫМ JSON (как уже делает
  `login.py`) с базовым набором (кортик, пистолет, бландербасс, лопата,
  ведро, фонарь, набор эмоций) — схема полей угадана (реальный plaintext
  для этого эндпоинта никогда не видели), не подтверждена живым тестом.
  Остальные вышеперечисленные эндпоинты (entitlements/ship/emblem/...) той
  же проблемой всё ещё страдают — не переопределены.
